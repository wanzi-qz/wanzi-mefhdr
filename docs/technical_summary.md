# 技术总结（M5 · 项目收官）

一句话版本：**一条不训练任何模型的多曝光融合 HDR 链路，从手机连拍到定量评测，
跑通了全流程，也摸清了传统方法的能力边界。**

---

## 1. 最终链路与成绩

```
连拍输入(JPG/RAW) → 曝光对齐(MTB默认) → 三权重图(对比度/饱和度/适度曝光)
                 → 拉普拉斯金字塔融合 → sRGB 输出 + 过曝/欠曝统计
```

| 验证集 | 结果 | 说明 |
|---|---|---|
| 自采 4 场景（夜景×2 + 白天×2） | 全部跑通，单场景 11~18s @4096×3072 | scene01/02 无重影 |
| Kalantari 测试集（15 场景） | PSNR-μ 17.43 / SSIM-μ 0.7525（最优增益口径 19.38dB） | 零调参，同一套配置 |

## 2. 核心参数调优经验（按踩坑顺序）

1. **RAW 显影口径（影响最大）**：`no_auto_bright=True` 是底线。rawpy 默认
   自动亮度会把三档曝光抹成一样亮（F2），一切曝光相关的统计随之作废。
   16bit 线性域读入 → 手动 sRGB gamma 显影，与相机 JPG 直出对齐口径。
2. **权重参数几乎不用调**：Mertens 三权重（对比度/饱和度/适度曝光）对参数
   不敏感，中间调宽度 w=0.2 在四个自采场景和 15 个 Kalantari 场景都工作正常。
   真正影响结果的是**输入质量**（EV 分离度、对齐），不是权重细节。
3. **金字塔层数**：默认 6 层对 1000~4000px 图像都够。层数再多融合差异不可见，
   只增加耗时。
4. **MTB 金字塔层数**：log2(min(h,w))-8 层即可覆盖 ±60px 的手持抖动
   （scene01 实测 60px 一次命中）。
5. **过曝/欠曝统计阈值**：JPG 上用 250/5，RAW 显影后用 0.98/0.02（归一化域）。
   阈值口径要跟输出域绑定，跨域比较无意义。

## 3. 五个失败案例（详见 docs/failures.md）

| # | 一句话 | 根因类型 |
|---|---|---|
| F1 | cv2.imwrite 中文路径静默失败 | 环境兼容 |
| F2 | rawpy 自动亮度抹平三档曝光 | 库默认值陷阱 |
| F3 | 对齐误差全错——"校正量"和"位移量"差个负号 | 接口语义 |
| F4 | 光流大位移全局估计失效（≥10px） | 算法能力边界 |
| F5 | 重新构图式连拍四种对齐全失效（视差） | **原理性边界** |

共同教训：**每次"结果不对"先怀疑自己的口径（单位/符号/默认值），再怀疑算法；
用独立实验（网格搜索、哈希、增益诊断）裁决，不靠肉眼。**

## 4. 传统方法的适用边界（项目核心结论）

**够用的场景**（传统方案性价比极高）：
- 固定机位或轻微手持抖动（平移为主，MTB 0.6s 解决）
- 静态场景（Kalantari 静态子集 PSNR-μ 18~21.5，单张 0.8s CPU）
- 工业相机/监控这类可控拍摄条件的场景——正好对应海康 Local Tone-mapping 的使用环境

**必须上深度方法的场景**：
- 前景运动（行人、车辆）：Kalantari 运动子集 SSIM-μ 掉到 0.54~0.75，
  只有逐像素去鬼影网络能救
- 重新构图式拍摄（视差）：任何全局几何模型原理上无效（F5 实测四种方案全败）

**跨论文指标不可直接比**：FlexHDR 报 Kalantari 数据集 PSNR-μ 42.7，原论文
口径约 21——μ 参数、输出域不同。引用别人数字必须核对协议，否则只报自己复算值。

## 5. 遗留与可扩展方向

- MEF-SSIM（无参考指标）未实现：现成库缺失、自实现易错，报告中明示
- 光流大位移失效（F4）未修：金字塔加层 + 梯度秩归一化是候选方向
- 去鬼影权重（基于对齐残差的逐像素置信度）是纯经典路线内最值得做的下一步
- 深度方案对比只做了文献数字核对，未本地复跑 DeepU-Fuse（GPU 资源限制）
